# 0.19.0 — 2026-11-08

## Added

- **`secedgar_get_filing` `find`** ([#238](https://github.com/cyanheads/secedgar-mcp-server/issues/238)) opens the page at a phrase in the document text and lists up to 20 `occurrences` (`offset`, `context`) beside `occurrences_total`; `offset` is where the search starts. A phrase with no occurrence at or after `offset` fails `phrase_not_found`.
- **Ticker spellings** ([#235](https://github.com/cyanheads/secedgar-mcp-server/issues/235)): uppercase `UEC.N` (venue codes `N`, `O`, `OQ`, `A`, `P`, `K`, `PK`), run-together preferreds `CFGPH`, and class-only roots `GLOP` resolve in every tool that resolves a company, with the reading in `resolvedAs`, `effectiveQuery`, or a `secedgar_compare_companies` caveat.
- **Concept aliases** ([#240](https://github.com/cyanheads/secedgar-mcp-server/issues/240)): `secedgar_get_financials`, `secedgar_compare_companies`, and `secedgar_fetch_frames` accept a concept's label spelling (`capital_expenditures`, `cash_and_cash_equivalents`, `total_assets`) and lowerCamelCase (`operatingIncome`); `secedgar_search_concepts` matches the label spellings too.

## Changed

- **Mirror reads go live where SEC may hold newer data** ([#234](https://github.com/cyanheads/secedgar-mcp-server/issues/234)), with `EDGAR_MIRROR_FALLBACK_LIVE` on: the ticker index each `EDGAR_TICKER_CACHE_TTL`, a filer's XBRL facts once it has filed XBRL since the store was compiled, and frames for a period still open for filing. Strict mode sends nothing to SEC for these.
- **A failed live read is answered from the store only where it holds the answer** ([#234](https://github.com/cyanheads/secedgar-mcp-server/issues/234)). For a filer the store lacks, or an open frames period with no stored frame, the live failure stands. A live 404 for a tag the store holds for that filer answers the stored row; a tag it lacks stays `null`. A filer stays on the store for 60 s only after a failure SEC itself returned.
- **`secedgar_compare_companies` and `secedgar_get_financials` start every read at once** ([#234](https://github.com/cyanheads/secedgar-mcp-server/issues/234)): each company's companyfacts read, and each tag's companyconcept read. Results, and which failure fails the call, are unchanged.
- **A 5xx that outlasts the retries fails `sec_unavailable`** ([#233](https://github.com/cyanheads/secedgar-mcp-server/issues/233)): `ServiceUnavailable`, `retryable`, with a hint. A 504 was `Timeout` (-32004) and is now -32000 like 500, 502, and 503. Declared on the 13 tools that declare `sec_unreachable`.
- **Breaking: an uppercase ticker ending in a non-US exchange code** (`.L`, `.T`, `.TO`, `.HK`, `.ME`) fails each tool's not-found reason, with a sentence that EDGAR indexes SEC registrants by US ticker, name, or CIK ([#235](https://github.com/cyanheads/secedgar-mcp-server/issues/235)). A few such inputs used to reach the right company by coincidence through name matching.
- **An uppercase two-letter dotted initialism without its closing period reads as a venue code** ([#235](https://github.com/cyanheads/secedgar-mcp-server/issues/235)): `H.P` is Hyatt, `J.P` Jacobs, `B.P` Barrick. `H.P.` and `h.p` still reach HP.
- **Breaking: `secedgar_dataframe_query` refuses a column alias, table alias, or CTE spelled like a DuckDB metadata view** as `system_catalog_access` (`SELECT period_end AS pg_class FROM df_…`); rename it. The gate comes with mcp-ts-core 0.13.19.
- **Breaking: `secedgar_search_filings` fails `unsupported_entity_scope` for a negated token beside a scoping token for a different company** (`ticker:AAPL -ticker:MSFT`, `ticker:AAPL NOT cik:789019`), which 0.18.1 answered with the scoped company's filings ([#243](https://github.com/cyanheads/secedgar-mcp-server/issues/243)).
- **`secedgar_dataframe_describe` and `secedgar_dataframe_drop` answer a `name` not shaped `df_XXXXX_XXXXX` as unknown** (an empty list; `dropped: false`), not with a reasonless storage error.
- **`secedgar_dataframe_query` fails `WITH … INSERT` as `non_select_statement`**, where it was `invalid_sql`, and `non_select_statement` no longer carries `data.statementType`.
- **`secedgar_dataframe_query` runs `range()` and `generate_series()` over constant arguments**, which it refused as `plan_operator_not_allowed`; a column or subquery argument is still refused (mcp-ts-core 0.13.20).

## Fixed

- **`secedgar_get_filing` `section` lands on the section a table-of-contents row links to** ([#239](https://github.com/cyanheads/secedgar-mcp-server/issues/239)), not on the row.
- **Concurrent first stagings share one canvas** ([#241](https://github.com/cyanheads/secedgar-mcp-server/issues/241), thanks [@cfei28](https://github.com/cfei28)!). Tables from a fresh process's first concurrent calls answered `missing_table` while `secedgar_dataframe_describe` still listed them.
- **`secedgar_search_filings` `ticker:`/`cik:` tokens** ([#243](https://github.com/cyanheads/secedgar-mcp-server/issues/243)): a negated token alone (`-ticker:AAPL`, `NOT cik:320193`) or a second entity token fails `unsupported_entity_scope` before any SEC request, and a `+` before a token is removed with it. These returned the excluded company's filings or none.
- **Near-match company and concept suggestions score in time linear in the input.**
- **The submissions, archive-page, and full-index caches hold at most 448 MiB of parsed SEC documents** by the service's estimate, dropping the entries used longest ago.
- **`secedgar_get_filing`'s table-of-contents link pass runs in time linear in the document.**
- **A scheduled mirror refresh stops at shutdown**, and one skipped because another process holds the sync lease logs at `info` instead of `error`.

## Security

- **`secedgar_dataframe_describe` no longer lists every caller's dataframes over HTTP with `MCP_AUTH_MODE=none`**, where all callers share one canvas ([#242](https://github.com/cyanheads/secedgar-mcp-server/issues/242)). **Breaking:** without `name`, or with an empty one, it fails `listing_unavailable` there. By-name describe and every query still answer.
