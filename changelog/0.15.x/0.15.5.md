# 0.15.5 — 2026-09-09

## Added

- **`secedgar_dataframe_query`** gains `row_count_capped` — `true` when `row_limit` bound the query, so `row_count` is that cap rather than a total ([#109](https://github.com/cyanheads/secedgar-mcp-server/issues/109)).

## Changed

- **`secedgar_dataframe_drop`** now registers through `disabledTool()` when `EDGAR_DATAFRAME_DROP_ENABLED` is off — still absent from `tools/list` and uncallable, but shown on the HTTP landing page and Server Card manifest as disabled, with its reason and enable hint ([#103](https://github.com/cyanheads/secedgar-mcp-server/issues/103)).
- **Every dataframe-producing tool** now names both `secedgar_dataframe_describe` and `secedgar_dataframe_query`, describe-then-query, in its tool description, `dataset.name` field, and runtime guidance whenever a `df_<id>` handle is staged; `secedgar_get_financials` and `secedgar_compare_companies` gained a `notice` enrichment field so that guidance actually reaches the wire instead of being stripped ([#104](https://github.com/cyanheads/secedgar-mcp-server/issues/104)).
- `secedgar_dataframe_describe` and `secedgar_dataframe_query`'s descriptions replace their stale producer enumeration (5 and 3 of 11 named) with a shape description ([#104](https://github.com/cyanheads/secedgar-mcp-server/issues/104)).

## Fixed

- **`secedgar_dataframe_query`** now discloses truncation when `row_limit` alone bound the result — previously `rowCount === rows.length` on that path hid the cap entirely. The guidance and `format()` output name the cap rather than claiming a false total ([#109](https://github.com/cyanheads/secedgar-mcp-server/issues/109)).
