# 0.15.10 — 2026-10-04

## Changed

- **Tool errors carry their request ID** — an error result ends with `request <id>` and its `data` carries `requestId`, the id the server's log records for that call carry (mcp-ts-core 0.13.10, [cyanheads/mcp-ts-core#576](https://github.com/cyanheads/mcp-ts-core/issues/576)).
- **Argument handling** — an integer sent for a string argument is repaired before validation, and a rejection names the alias rewrite that touched the call (mcp-ts-core 0.13.9, [cyanheads/mcp-ts-core#487](https://github.com/cyanheads/mcp-ts-core/issues/487), [cyanheads/mcp-ts-core#468](https://github.com/cyanheads/mcp-ts-core/issues/468)).
- **Client error data** — stack traces (mcp-ts-core 0.13.7) and request context (0.13.8) no longer reach it, and an output-contract violation returns `-32603` (0.13.8).
- **`ctx.log`'s client mirror** sends only records at or above `MCP_LOG_LEVEL` and masks sensitive fields (mcp-ts-core 0.13.11).
- **Dataframe canvas** — scratch files live in a private directory, concurrent spills no longer corrupt each other, and DuckDB errors classify by DuckDB's error class with host paths redacted (mcp-ts-core 0.13.9); `missing_table` means a missing table (0.13.8).
- **Startup line** lists disabled tools separately, e.g. `16 tool(s) (+1 disabled: secedgar_dataframe_drop)` (mcp-ts-core 0.13.8).
- **MCP SDK `@modelcontextprotocol/server` ^2.2.0** — a 2026-07-28 POST without `MCP-Protocol-Version` is refused `400` (SDK 2.1.0 transport behavior, adopted in mcp-ts-core 0.13.9).
- **Recovery hints** — handlers no longer forward declared hints by hand; the framework fills them from each tool's `errors[]` contract (mcp-ts-core 0.13.10, [cyanheads/mcp-ts-core#579](https://github.com/cyanheads/mcp-ts-core/issues/579)). Internal only: callers receive the same hint text.
- **Dockerfile** — the image drops the musl-only native bindings its glibc runtime never loads (`scripts/prune-musl-packages.ts`), gains a `HEALTHCHECK` and an `org.opencontainers.image.version` label from an `APP_VERSION` build arg, and no longer sets the unread `MCP_FORCE_CONSOLE_LOGGING`.
- **Configuration docs** — `.env.example` and the README config table document `LOG_TOOL_FAILURE_PAYLOADS` / `LOG_TOOL_FAILURE_PAYLOAD_MAX_BYTES` and `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` (mcp-ts-core 0.13.8), plus the per-signal OTLP endpoints and base-endpoint behavior (0.13.7). README tool entries keep to three bullets.
- **Ignore rules** — `.gitignore` ignores `.env*` except the templates; `.dockerignore` excludes `.env*`, the MCP registry token files, and `.agents`; `.mcpbignore` excludes `/docs/idea.md`, `/logs/`, `/.cache/`, and `/data/` (the default `EDGAR_MIRROR_PATH` location); `package.json` `files` excludes `dist/*.mcpb`.
- **CodeQL workflow** runs one job per language: `Analyze (actions)` and `Analyze (javascript-typescript)`.
- Framework skills, scripts, and `CLAUDE.md` / `AGENTS.md` re-synced to the framework template.

## Fixed

- **Multi-arch Docker images install each architecture's DuckDB binding** ([#150](https://github.com/cyanheads/secedgar-mcp-server/issues/150)) — production dependencies install in a `deps` stage on `$BUILDPLATFORM`, cross-installing with `--os`/`--cpu` and running `scripts/install-otel.ts`, so an amd64 image built with `--build-arg OTEL_ENABLED=false` keeps `@duckdb/node-bindings-linux-x64`.
- **`server.json`'s `streamable-http` entry selects the HTTP transport** — it sets `MCP_TRANSPORT_TYPE` to `"value": "http"`, and both npm entries' `runtimeHint` is now `npx` (was `bun`).
