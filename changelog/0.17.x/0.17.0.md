# 0.17.0 — 2026-10-26

## Added

- **secedgar-guide Agent Skill**: the server publishes `skills/secedgar-guide/SKILL.md` and serves it over MCP as `skill://secedgar-guide/SKILL.md` through the Skills extension; plugin hosts load it from the package. It routes each ownership question to the right tool, traces where CIKs, accession numbers, CUSIPs, and fund series IDs come from, and lists the coverage limits to check before reporting data absent.
- **Agent Plugins manifests**: root `plugin.json` and `mcp.json` for hosts that read the Agent Plugins format (Codex, Cursor, GitHub Copilot, VS Code, Kiro).

## Changed

- **Enrichment notices that embed caller or SEC text** pass it through `escapeMarkdownInline`: the `secedgar_search_filings` zero-hit query, the `secedgar_search_concepts` no-match search text, the `secedgar_get_insider_transactions` company, the `secedgar_get_material_events` entity name, the `secedgar_find_holders` issuer phrase, and the `secedgar_get_filing` section and document filenames. `content[]` now reads back as the literal input; `structuredContent.notice` carries the backslash escapes.
- **Packaging**: `.mcpbignore` lines are root-anchored; `package.json` `files` and the Docker image include `skills/`; the image creates a `bun`-owned `/usr/src/app/data` for the default mirror path and labels itself `secedgar-mcp-server`. `bunfig.toml` `minimumReleaseAge` drops from 3 days to 1 day.
- **README** gains a Skills table and a reorganized Getting started (hosted and local `claude mcp add`, one `npx` block). Framework skills and four framework scripts are resynced, with `add-skill` new.

## Fixed

- **Dataframe join keys** ([#208](https://github.com/cyanheads/secedgar-mcp-server/issues/208)): `secedgar_get_beneficial_owners` (tool description and `dataset` output) now says 13D/G rows join insider dataframes on `issuer_cik` and 13F and NPORT-P dataframes on `cusip`, where it claimed a 13F join on issuer CIK; `secedgar_get_fund_holdings` `dataset` says NPORT-P rows join 13F and 13D/G rows on `cusip`, where it claimed an insider join.
- **`secedgar_find_holders` `quarter`** says a quarter still inside its 45-day deadline returns the managers that filed early, where it said "returns nothing".
- **Dataframe TTL** is described as fixed when the table is staged, not sliding: `secedgar_dataframe_describe` `expires_at`, `EDGAR_DATASET_TTL_SECONDS` in `.env.example`, `CLAUDE.md`, and `AGENTS.md`. Queries never extended it.

## Dependencies

- `@cyanheads/mcp-ts-core` ^0.13.16 → ^0.13.18:
  - HTTP requests no longer retain about 71 KiB each until shutdown; the 0.13.16 framework that 0.16.0 shipped on leaked that per request under sustained traffic (0.13.17, [mcp-ts-core#786](https://github.com/cyanheads/mcp-ts-core/issues/786)).
  - The `secedgar_search_filings` `Query:` trailer line in `content[]` renders the query as a code span, so a copied query carries no backslashes; `structuredContent.effectiveQuery` is unchanged (0.13.18).
  - The `secedgar_dataframe_query` refusal of an unqualified `current_schema` now says the bare name reads as the function unless a column of that name is in scope, and its recovery says to qualify the column (`<table>.current_schema`); the `denied_function` reason is unchanged (0.13.18).
  - The `.mcpb` bundle no longer ships the repository's `src/`, `tests/`, `scripts/`, `docs/`, or `changelog/`, better-sqlite3's node-gyp build output (`build/config.gypi` and `build/Makefile`), or the framework's build-only files; the bundle drops from 3,425 files to 2,933 (anchored `.mcpbignore` lines plus the resynced `scripts/clean-mcpb.ts`, 0.13.18).
- `@duckdb/node-api` ^1.5.6-r.2 → ^2.0.0-r.1: dataframes run on DuckDB 2; the framework's SQL gate covers it and refuses its single-file reader functions `read_single_csv_file`, `read_single_json_file`, and `read_single_parquet_file` (mcp-ts-core 0.13.17).
- `@modelcontextprotocol/server` ^2.3.1 → ^2.4.0, through the framework.
