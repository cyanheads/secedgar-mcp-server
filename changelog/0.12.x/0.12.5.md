# 0.12.5 — 2026-07-26

## Added

- **`secedgar_fetch_frames` `offset`** — 0-based rank to start the page at over the sorted frame. The response echoes the effective `offset` and carries `next_offset` while companies remain, so ranks past `limit` stay reachable when no canvas is available; the frame is fetched whole and sliced, so paging is contiguous and stable. An offset at or past the reporter count returns an empty page with a `notice` enrichment naming the total. ([#89](https://github.com/cyanheads/secedgar-mcp-server/issues/89))
- **`secedgar_get_institutional_holdings` `offset`** — the same shape over the ordered position list of one 13F information table, with `offset`/`next_offset` in both `structuredContent` and `format()`. ([#94](https://github.com/cyanheads/secedgar-mcp-server/issues/94))
- **`entity_not_found` declared error reason** on `secedgar_search_filings` (`NotFound`, -32001) — a `cik:` targeting token on a pre-2001 date range naming a CIK with no EDGAR submissions history. ([#93](https://github.com/cyanheads/secedgar-mcp-server/issues/93))

## Changed

- **`formatDocList` renders every filename** — the first `MAX_DOCUMENTS_IN_FORMAT` (10) entries per category keep type/size/description, and the remainder now follow as bare names instead of a `+N more` count. Filenames are the selectable keys for the `document` input, so `content[]` and the uncapped `structuredContent.documents` carry the same catalog. ([#88](https://github.com/cyanheads/secedgar-mcp-server/issues/88))
- **`document_not_found` and `no_documents` messages carry a catalog** — the new `renderDocumentCatalog` appends a labeled per-category block (capped at `MAX_DOCUMENTS_IN_ERROR` = 10, each line stating the category's true total and how many entries were withheld). Both recovery hints now point at that list rather than at `documents.primary` in error data. ([#88](https://github.com/cyanheads/secedgar-mcp-server/issues/88))
- **`secedgar_get_financials` `ambiguous_company` message lists the candidates** — CIK, name, and ticker for up to 10 matches are rendered into the message text, not only into `data.matches`. ([#90](https://github.com/cyanheads/secedgar-mcp-server/issues/90))
- **`secedgar_company_analysis` insider step** — describes `secedgar_get_insider_transactions` as Form 4 / 4-A coverage and routes Form 3 initial statements and Form 5 annual statements to `secedgar_search_filings` (`forms: ["3", "5"]`) plus `secedgar_get_filing`. The same correction lands in the tool table and prose of README, `CLAUDE.md`, `AGENTS.md`, and `.codex-plugin/plugin.json`. ([#92](https://github.com/cyanheads/secedgar-mcp-server/issues/92))
- **`scripts/clean-mcpb.ts` and `scripts/lint-packaging.ts` handle native bindings** — `NATIVE_BINDING_ENTRY` (`node_modules/@duckdb/node-bindings-*`) is stripped from the packed `.mcpb` alongside the existing agent-doc strip, and `checkBundleEntries` reports the two classes separately. A platform slice would otherwise pin the bundle to its build host and push it past the 25 MB registry cap.
- **`scripts/devcheck.ts` outdated gate** — `(peer)` rows are skipped (a peer range declares the lowest supported version, not the version to track) and any row where `Update` equals `Current` is no longer a finding, whether held by `minimumReleaseAge` or by a range that deliberately caps below latest. The gate now fails only on being behind within the declared range.
- **`scripts/check-dependency-specifiers.ts` scans `overrides`** under the strict no-floating rule — an override exists to hold a transitive off a vulnerable version, so a floating specifier there re-resolves the pin it was added to enforce.
- **`.gitignore`** — `/data/` is anchored to the repo root, replacing the unanchored `data/` rule and the two re-include exceptions that kept `src/services/edgar/data/former-names.json` tracked.
- **`Dockerfile`** — the optional OTel install runs `bun add --omit=dev --ignore-scripts`.
- **Skills synced to mcp-ts-core 0.11.0** — `api-canvas`, `api-config`, `api-utils`, `field-test`, `git-wrapup`, `orchestrations` (with its `field-test-fix`, `fix-wrapup-release`, and `maintenance-release` workflows), and `tool-defs-analysis`.

## Fixed

- **`secedgar_get_insider_transactions` bare-CIK 404** — a numeric CIK absent from the ticker cache resolves to a name-less, ticker-less match whose submissions feed 404s. That 404 is now converted to the declared `company_not_found` with a message pointing at `secedgar_company_search` and naming the accession-number-prefix trap, instead of surfacing the raw SEC URL. A cache-hit or ticker-resolved match that 404s still propagates unchanged. ([#91](https://github.com/cyanheads/secedgar-mcp-server/issues/91))
- **`secedgar_search_filings` pre-2001 bare-CIK 404** — `serveSubmissionsArchive` resolves the `cik:` token against the ticker cache before fetching, and converts only the bare-CIK 404 into `entity_not_found`. The lookup is confined to the pre-2001 archive arm, leaving the EFTS path untouched. ([#93](https://github.com/cyanheads/secedgar-mcp-server/issues/93))
