# 0.20.0 — 2026-11-17

## Changed

- **A `secedgar_get_institutional_holdings` quarter miss names the resolved filer and the newest 13F-HR filed** ([#254](https://github.com/cyanheads/secedgar-mcp-server/issues/254)). The message carries the filer's name and CIK, `data` adds `resolved_cik`, `resolved_name`, and `latest_quarter`, and the hint carries the retry call.
- **The `secedgar_get_institutional_holdings` operating-company error names the CIK** and suggests `secedgar_search_filings`.
- **The `secedgar_get_institutional_holdings` `no_filings_found` guidance** names the no-`quarter` path where the recent window holds only 13F-HR/A amendments.
- **The `no_info_table` message of a 13F-HR with no XML information table** names the filing date and says the filing has none.
- **A missing `df_<id>` table fails `missing_table`** as `Canvas table "df_X" does not exist — it may have expired or was never registered.`, with `data.tableName`; it read `Dataframe 'df_X' does not exist or has expired.`.
- **`invalid_sql` errors no longer carry `data.statementType`.**
- **The `invalid_sql` and `non_select_statement` recovery hints** name `secedgar_dataframe_describe` where the framework's generic text said "this server's dataframe-describe tool". The hints for a missing function, type, collation, or schema and for the IO class no longer send callers to list the staged tables, which HTTP with auth none refuses.
- **The `secedgar_dataframe_query` `row_count` description** says a `register_as` count covers every row of the registered table.
- **The `secedgar_get_financials` `dataset` description** names its column mapping: `entity_name`, `period_start`/`period_end`, `source_filing_fy`/`source_filing_fp`.
- **CPU-timed tests pass `0` as their per-test timeout** ([#250](https://github.com/cyanheads/secedgar-mcp-server/issues/250)).

## Fixed

- **`secedgar_fetch_frames` stages the filer column as `company_name`**, as its inline rows name it ([#253](https://github.com/cyanheads/secedgar-mcp-server/issues/253)). Breaking: `SELECT entity_name` against a `secedgar_fetch_frames` dataframe now fails `invalid_sql`.
- **The mirror's ticker sync deletes symbols that left SEC's ticker files** ([#247](https://github.com/cyanheads/secedgar-mcp-server/issues/247)), so they resolve as they do live, as a former ticker or no match, instead of as current listings. A `company_tickers.json` listing no ticker fails the sync, as does a refresh that would delete over a quarter of either kind's stored rows (`init` applies it), and fund rows are deleted only when `company_tickers_mf.json` loaded.
- **`secedgar_company_search` and `secedgar_get_material_events` return `older_filings_unexamined`** beside `history_scanned_through` ([#248](https://github.com/cyanheads/secedgar-mcp-server/issues/248)); `false` means the scan reached the filer's first filing, and the text then reads `no older filings on EDGAR` instead of `older filings not examined`.
- **`secedgar_dataframe_query` truncation notices name the lever that applies** ([#252](https://github.com/cyanheads/secedgar-mcp-server/issues/252)). A `register_as` call's notice names the registered table instead of advising `register_as`, "(capped)" is gone from the uncapped notice, and a result at the 10,000-row cap, a `row_limit` of 10,001 to 100,000 included, no longer advises raising `row_limit`.
- **A `preview` above `row_limit` is served at `row_limit`** instead of failing `invalid_query_bounds`.
- **A mirror run syncs both layers and rejects with the first failure**, so a failed ticker download no longer skips the company-facts sync; a stopped run starts no company-facts sync.
- **The fund-ticker file fetch rethrows the caller's cancellation** instead of degrading to no fund rows.
- **The ticker-file parser skips an entry with an empty ticker or no title.**
- **A `secedgar_get_institutional_holdings` miss with no `quarter`** no longer prints `for quarter "undefined"`; it reads `in its recent submissions window`.

## Security

- **`secedgar_dataframe_query` no longer reads the SQL text in the server before DuckDB parses it** ([#251](https://github.com/cyanheads/secedgar-mcp-server/issues/251)); DuckDB alone parses it. A `df_<id>` handle inside a comment, a string or dollar-quoted literal, a CTE name, or an alias now runs instead of failing `missing_table`, and an unterminated `'…` or `/* …` holding one fails `invalid_sql` with DuckDB's parser message.
